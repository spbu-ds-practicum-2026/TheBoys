# Инфраструктура проекта (`infra/`)

Модуль оркестрации, балансировки и хранилища данных распределенной системы.

## Архитектурные компоненты

### 1. Балансировщик Nginx (`infra/nginx/nginx.conf`)
- **Единая входная точка:** Принимает внешние HTTP-запросы и постоянные WebSocket-соединения (`/ws`).
- **Безопасность:** Блокирует внешний доступ к внутренним межсервисным эндпоинтам (`location ^~ /internal/` возвращает `403 Forbidden`).
- **Динамический Service Discovery:** Использует встроенный DNS Docker (`resolver 127.0.0.11 valid=5s`) и dynamic variable upstream (`set $app_upstream "app:8000"`). При масштабировании узлов приложения (`docker compose up --scale app=N`) Nginx автоматически распределяет запросы между всеми живыми контейнерами без перезагрузки.

### 2. Схема PostgreSQL (`infra/postgres/init.sql`)
Инициализирует структуры данных согласно ТР:
- `users` — учетные записи и хеши паролей.
- `node_registry` — реестр узлов системы (роли `app`, `storage`, `worker`), отметки heartbeat для обнаружения сбоев.
- `conversations` — диалоги с монотонным счетчиком `last_seq` и уникальным индексом на пару собеседников `UNIQUE(LEAST(user1_id, user2_id), GREATEST(user1_id, user2_id))`.
- `messages` — история сообщений с гарантией упорядоченности (`UNIQUE(conversation_id, seq)`) и идемпотентности (`UNIQUE(conversation_id, client_msg_id)`).
- `conversation_reads` — позиции прочтения сообщений участниками.
- `sessions` — активные WebSocket-подключения клиентов к конкретным узлам приложения (`node_id`).
- `tracks` — каталог аудиофайлов.
- `replicas` — размещение двух реплик каждого трека на узлах хранения.
- `jobs` — очередь фоновых задач (репликация) с поддержкой распределенной аренды (lease) и токенов ограждения (fencing tokens).

## Локальный запуск

```bash
# Старт всей системы:
docker compose up --build

# Старт с двумя взаимозаменяемыми узлами приложения:
docker compose up --scale app=2 -d
```
